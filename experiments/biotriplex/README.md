# BioTriplex：锁定的全文外部测试集（2026-11-03）

可行性核查见 `feasibility.md`。适配、冒烟测试和评测集运行都已完成，结果见文末"评测集结果"。

## 数据
- 来源：https://github.com/PanagiotisFytas/BioTriplex 的 `Preprocessed BioTriplex/splits.json`，commit 记录在 `data/SOURCE_COMMIT`。
- 代码是 MIT 许可证，数据许可没有单独说明，所以数据、生成的文章和金标都只留在本地（已写进 `.gitignore`）。
- Windows 下直接 `git clone` 会检出失败，因为有文件名含 `:`。`splits.json` 本身可以直接下载。

## 评测集（运行前锁定，`sample_biotriplex.json`）
- 评测集：val + test 共 30 篇。其中 21 篇有关系，共 151 个金标关系，115 个只出现在摘要以外。
- 调试集：train 中有关系的 5 篇（种子 20261103），只用来检查实体合并规则和适配是否正确，不用来选方法或阈值。
- `BTX<pmcid>` 是全文，`BTXA<pmcid>` 只有摘要，两者用同一份金标；摘要部分的 block 编号相同。

## 适配规则（`prepare.py`，已冻结）
- 每个小节写成一个 `<sec>`，每个非空行写成一个 `<p>`。摘要以 "Title:" 行开头，整体放进 `<abstract>`。
- 小节名去掉 " Rev" 后缀（修订版的标注，取代原版，不会重复）。原数据没有记录小节顺序：带编号的按编号排，其余按"引言、方法、结果、讨论、结论、其他"排。
- 实体没有 ID，按以下规则合并：
  - 同类型提及在小写化、统一空白和连字符、去掉不连续提及中间的 "..." 后，文本相同的合并；
  - 文中 "全称 (缩写)" 或 "缩写 (全称)" 紧挨着出现的，也合并。
  - 在 5 篇调试文章上逐条检查过，缩写、全称和大小写变体都合并正确。
- 基因–疾病之间只要有一个链接的关系不是 "no relation"，就算有关系（21 种类型合并）。只有 "no relation" 链接的配对另存为明确否定；评测集里没有这种配对。
- 共有 5 个提及或链接因位置对不上而丢弃。

## 评分（`evaluate.py`）
- 直接复用 BioRED 的评分器：按字符位置重叠对齐，一对一匹配，按文章做 bootstrap。
- 另外报告：
  - 按关系出现的位置拆分的召回率："摘要中有链接"和"只在摘要以外"；
  - 真阳性上的陈述来源一致性：我们输出的 this study / background / both，对比 BioTriplex 的 result / background 标注。

## 事先定好的判读（看结果之前写下）
1. **以召回率为主要指标。** BioTriplex 只标注了文中用关系词明确表达的关系，每篇只有约 3–8 个，并不是穷举所有关系。冒烟测试中，V6 报出的不少配对（如 PTCH1 与基底细胞癌）在原文里明显有关系，但没有被标注。所以精确率会被系统性低估，只能作为参考，并按"两个实体都在金标里但没有标关系"和"实体不在金标里"分开报告。
2. **读全文的收益** = V6 全文和 V6 摘要在"只在摘要以外"那 115 个关系上的召回率差，用同一份金标、同一个评分器。
3. **和 PubTator3 比较**：PubTator3 的关系预测只来自摘要，所以它是"只读摘要的标准资源"基线，比较重点在召回率。
4. V6 全文的结果按两种口径报告：有效结果的文章，以及部署口径（失败的文章按空输出计）。确定性前处理（`normalize.py --filter`）作为第二行报告。

## 评测集结果（2026-11-03，V6 = Claude Opus 5.5，medium）

### 运行情况
- 60 个输入（30 篇全文 + 30 篇摘要），共 $12.02（按标价），2,451 秒。
- 全文有效 25/30，摘要有效 28/30：
  - 4 篇全文（3320601、4302655、4550874、5444857）和 2 篇摘要（3320601、4550874）被 API 的安全机制拦截。4 篇全文里，2 篇与病原体感染有关（3320601 肺炎链球菌鼻腔挑战、5444857 钩端螺旋体），另 2 篇不是（4302655 关节炎易感小鼠的免疫耐受、4550874 肌营养不良模型的 Connexin43）。触发原因不明。每篇按原样重试了一次，仍被拦截，之后没有再重试，也没有换模型。
  - BTX9489697 修复一次后仍不合格（主关系类型），重试一次结果相同。
- 确定性前处理（只重放首次输出、不修复）：全文有效 22 篇、摘要 25 篇，结果和原始运行基本一致（全文 F1 0.534 对 0.525），下表只列原始运行。

### 判读（按事先定好的规则）
1. **输入相同时，V6 和 PubTator3 没有可分辨的差别**：只读摘要时，F1、召回率和精确率的差值区间都跨 0。
2. **读全文带来了召回率的大幅提升**：同一个 V6，全文比摘要的召回率高 0.45；在只出现于摘要以外的关系上，召回率从 0.20 升到 0.79。这一收益来自输入范围，不来自提示。
3. **V6 全文对 PubTator3**：召回率高 0.51，F1 高 0.16，但 F1 区间下限只有 0.003，接近 0。
4. **精确率偏低且只能作参考**：V6 全文报出的、不在金标里的 172 对 supported 中：
   - 91 对的两个实体都在金标里，只是没有标关系（BioTriplex 的标注稀疏，冒烟测试中这类配对不少在原文里明显有关系）；
   - 44 对疾病不在金标里，19 对基因不在金标里，7 对两者都不在（多是基因家族、症状或非人类基因等 BioTriplex 不标的实体）；
   - 11 对是同一金标关系的重复配对。
5. **陈述来源**：在 109 个真阳性上，我们给出的来源与 BioTriplex 的 background/result 标注完全一致的有 81 个（74%），部分重叠 20 个，不一致 8 个。
6. **部署风险**：30 篇全文中有 4 篇（13%）两次都被安全机制拦截（其中 2 篇与感染有关，原因不明）。按部署口径，V6 全文的召回率是 0.722，F1 是 0.505。

### 局限
- 只有 25–28 篇有效文章，区间较宽。
- 金标是单名主标注者标的，关系一致性 0.71，而且不是穷举标注。精确率被低估的程度只做了单名作者的抽查（见下节）。
- PubTator3 的关系只来自摘要，所以"V6 全文 − PubTator3"混合了输入范围和方法两种因素；方法本身的比较以"V6 摘要 − PubTator3"为准。


## 精确率抽查（2026-11-03，单名作者，探索性）
`precision_check.py` 从 88 对"V6 全文判为 supported、两个实体 BioTriplex 都标了、但没标关系"的配对中随机抽 20 对，和 5 条 BioTriplex 关系（阳性对照）、5 条同段落共现但 BioTriplex 无关系且 V6 也没判的配对（阴性对照）混在一起，打乱后编号 P01–P30，由一名作者在 `precision_check/sheet.html` 里标注。
- 每条显示两个实体同时出现的段落（最多 6 段）。实体的提及取 BioTriplex 的标注加 V6 识别的同一实体，所有条目用同一条规则；页面上不显示系统输出、证据或金标。
- 答案在 `precision_check/biotriplex_precision_answers.csv`，汇总在 `precision_check/result.json`（`python experiments/biotriplex/precision_check.py --score`）。整个文件夹含原文段落，只留在本地。

| 类别 | 条目 | 判为有关系 | 推测性关系 | 没有陈述 |
|---|---:|---:|---:|---:|
| 抽查：V6 判、BioTriplex 没标 | 20 | 20 | 0 | 0 |
| 阳性对照（BioTriplex 有关系） | 4（P01 未作答） | 3 | 0 | 1 |
| 阴性对照（BioTriplex 无关系、V6 也没判） | 5 | 1 | 1 | 3 |

- 对照与 BioTriplex 一致 6/9。不一致的 3 条：阳性 P06（CXCL17 与流感）判为没有陈述；阴性 P07（TNF-α 与 ILD）判为推测性关系，P27（Akt 与肺癌）判为有关系。标注者在阴性对照上多数判"没有陈述"，说明不是一律判"有关系"。
- 抽查的 20 对全部判为有关系，比例的 95% 单侧下限约 0.86。
- **调整后的精确率（探索性）**：V6 全文共报 281 对 supported，其中 109 对是金标关系。如果把"两个实体都在金标里但没标关系"的 91 对按抽查比例算作正确，其余 81 对（实体不在金标里的 70 对、重复的 11 对）按最不利处理，全算错：
  - 按 20/20：精确率 (109 + 91) / 281 = 0.71；
  - 按 95% 下限 0.86：精确率约 0.67。
  - 原始数字是 0.39。
- 局限：只有一名标注者，样本 20 对；显示的段落用到了 V6 识别的提及（对照用同一规则）；标注者判断的是"段落是否陈述了关系"，比 BioTriplex 要求的"有明确关系词、属于 21 种类型之一"宽。这个结果只说明 0.39 明显低估了精确率，不能当作精确率的正式估计。


## 换模型复现：GPT-6.1 sol（2026-11-03，run set `biotriplex_gpt`）
同样的 V6 提示、同样的锁定评测集，模型换成 GPT-6.1 sol（Codex CLI，medium）。
- 全文 27/30 有效：3 篇修复后仍不合格（BTX6995577、BTX7578153、BTX9489697）。**Claude 被安全机制拦截的 4 篇文章，GPT 都正常完成了。**
- 摘要只完成 13/30：跑到一半 Codex 工作区额度用完（"Your workspace is out of credits"），剩下 17 篇没有开始。批处理脚本原先没识别这条错误，已改为按额度用尽处理（`run.py` 读取 Codex 的 error 事件，`batch.py` 停止开始新文章）。摘要那一遍的结果只是部分结果。

1. **全文带来的召回率提升在另一个模型上同样出现**，幅度相近（GPT +0.58，Claude +0.45）。这个收益不依赖特定模型。

4. 被 Claude 安全机制拦截的文章，换成 GPT 可以处理。
