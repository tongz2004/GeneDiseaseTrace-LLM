# GeneDiseaseTrace-LLM：复核结果与修改决策备忘（2026-11-03）

这份备忘按导师提出的四个问题整理本轮复核的结果：哪些结论现在有证据支持，哪些还不成立，论文必须改什么，以及需要你决定的事。所有数字都来自仓库内可以重跑的脚本，具体命令见文末。`main.tex` 已按第 6 节的定位重写（改写前的版本保存在 `paper/latex/main_pre_revision.tex`），所有改动都没有提交。

## 0. 先说结论

1. **论文里所有精确率都偏高。** 原评分允许一条金标关系同时算对我们的好几个配对。改成一对一匹配后，BioRED Test 上 V1 的 F1 从 0.542 降到 0.512（Test 50 篇样本从 0.551 降到 0.521），精确率从 0.853 降到 0.760。PubTator3 也受影响，但幅度小得多（0.716 → 0.680）。
2. **规则卡片降低了 F1。** 去掉卡片的最小提示（V6），在 Dev+Test 143 篇上严格口径 F1 高 0.114（95% 区间 [0.040, 0.197]）。卡片换来的精确率优势只有约 7 个百分点（区间跨 0），召回率却低约 19 个百分点。
3. **卡片的"格式更稳、成本更低"不是卡片本身的功劳。** 用确定性前处理离线重放首次输出后，V6 首次即合格的比例是 92%（V1 93%），费用反而比 V1 略低。
4. **两个系统在 BioRED Test 全部 100 篇上都不如 PubTator3：** V1 F1 0.511，V6 0.614，PubTator3 0.680。PubTator3 是在 BioRED Train 上训练的；它在 Train 上的 F1 是 0.857，Test 上是 0.680。
5. **召回率低来自我们卡片的具体内容，不是"写了规则"本身。** 在 V6 上只加入 BioRED 官方指南的实体规则（V7-E）或关系规则（V7-R），Dev 上的 F1 都没有显著变化（−0.015、−0.005），召回率仍比 V1 高约 23 个百分点。所以压低召回率的是 V1 卡片自己的证据标准。需要注意，V7 卡片比 V1 短（270–355 词对 1045 词），篇幅这个因素没有单独控制。
6. **单名作者的盲序案例审核（探索性）。** 16 条"只有 V6 判为有关系、BioRED 没标"的配对，与 10 条对照混在一起、打乱顺序后由一名作者标注：16 条都被判为摘要里陈述了关系，对照 9/10 与 BioRED 一致。这只能用来解释错误类型，不能用来修正整体精确率，也不能据此说 V6 优于 PubTator3 或 BioRED 系统性漏标（一名标注者、16 条来自 9 篇摘要，见第 4 节）。
7. **外部全文测试（BioTriplex，30 篇，运行前锁定）：输入相同时 V6 与 PubTator3 没有可分辨的差别；读全文让召回率大幅上升。**
   - 只读摘要：V6 与 PubTator3 的 F1 差 +0.019 [−0.09, 0.15]，召回率差 +0.034 [−0.08, 0.17]。
   - 同一个 V6，全文比摘要召回率高 0.448 [0.30, 0.59]；只出现在摘要以外的关系，召回率从 0.20 升到 0.79。
   - V6 全文对 PubTator3（关系只来自摘要）：召回率 0.813 对 0.306，F1 0.525 对 0.369，差 +0.156 [0.003, 0.29]。
   - 精确率 0.39，只能作参考：BioTriplex 不是穷举标注，V6 多报的配对里有一半以上两个实体都在金标里，只是没标关系。
   - 单名作者盲序抽查了其中 20 对，全部判为段落里陈述了关系（对照与 BioTriplex 一致 6/9）。把这类配对算作正确后，精确率约 0.67–0.71。这是探索性估计，只说明 0.39 明显偏低，不作为正式数字。
   - 30 篇全文中有 4 篇（其中 2 篇与感染有关，原因不明）两次都被 API 安全机制拦截；按部署口径，召回率 0.722。
   - **换 GPT-6.1 sol 复现**：全文的召回率提升同样出现（全文对摘要 +0.58，12 篇；只在摘要以外的关系召回率 0.85），但 GPT 的精确率更低，全文 F1 对 PubTator3 的优势不显著（+0.083 [−0.09, 0.23]）。所以稳健的结论是"全文提高召回率"，不是"F1 超过 PubTator3"。Claude 拦截的 4 篇文章，GPT 都能处理。GPT 摘要那一遍因 Codex 额度用完只完成 13/30。
   - **全文有监督基线（BioREx，PubTator3 的关系模型，本地逐段运行）**：本地 BioREx 只读摘要时与 PubTator3 无可分辨差别（F1 差 −0.039 [−0.14, 0.03]），说明复现可信。BioREx 读全文后召回率也升到 0.72，但精确率降到 0.18，F1 没有提升。输入范围相同（都读全文）时，V6 Claude 比 BioREx 的 F1 高 0.193 [0.09, 0.29]，GPT 高 0.129 [0.01, 0.25]，差距主要来自精确率；召回率无可分辨差别。局限：BioREx 在摘要上训练、逐段用于全文属于跨域。**混合盲法抽查**（单名作者，V6 和 BioREx 各 15 对，来源不可见，对照 9/10 一致）显示，在"两个实体都标了、只是没标关系"这一类配对上，两个系统有原文依据的比例相同（都是 13/15）；精确率差距主要来自 BioREx 多报的实体不在 BioTriplex 范围内的配对（疾病不在金标里 170 对，V6 是 44 对）和重复配对（38 对，V6 是 11 对）。调整后精确率 V6 约 0.69、BioREx 约 0.38，但未抽查的类别全按错误计。所以论文应写成"差距主要来自实体范围和实体合并"，而不是"LLM 的关系判断更准"。**第二轮抽查"疾病不在金标里"的配对**（各 15 对）：两个系统识别的"疾病"里各有 6/15 不是疾病（死亡、复发、器官、过程等），但 BioREx 这类配对是 V6 的近 4 倍；是疾病且有原文依据的比例 V6 9/15、BioREx 6/15。两类合并后，调整精确率 V6 约 0.79、BioREx 约 0.53（未抽查类别全按错误计），差距主要来自 PubTator3 管线在全文上报出的大量非疾病和范围外实体。细节见 `experiments/biorex/README.md`。
   - 细节见 `experiments/biotriplex/README.md`。
8. **大模型不能代替人工审核。** GPT-6.1 sol 和 GPT-6 luna 之间的一致性接近随机（κ ≈ 0），而且都没有在真正无关的配对上检验过。
9. **证据可追溯性还没有被评测。** 第 2 轮的证据包材料已经准备好，但还没有人工标注。

## 1. 当前最好的方法（核对过原文的数字）

| 方法 | 报告的结果 | 评测条件（不能直接横向比较） |
|---|---|---|
| PubTator3（NER 用 AIONER + GNorm2，RE 用 BioREx） | BioREx 在 BioRED 测试集上 79.6% F1 | 给定金标实体，多种实体类型、多种关系类型 |
| AIONER | BioRED 测试集上 Gene 约 92.4%，Disease 约 83–84% | 实体识别，不含 ID 标准化（GPT 给的 Disease 88.07 与原文表格不符） |
| BioCreative VIII BioRED，subtask 2 端到端 | 最好的成绩：实体对 55.84%，关系类型 43.03% | 端到端，全部实体类型，按概念 ID 评测 |
| CoRE（ACL 2026） | 在 BioRED 和 CDR 上优于只用 PLM 或只用 LLM 的方法 | PLM 置信度低的情况交给 LLM 检索并重新推理 |
| BioTriplex（2026） | 微调的 LLaMA 3.1 8B 优于零样本 GPT-4 和 Claude | 全文按小节切分，21 种细粒度关系 |
| 我们（V1 / V6），BioRED Test 100 篇 | F1 0.511 / 0.614 | 只评基因–疾病，按字符位置重叠对齐（非 ID），一对一匹配 |
| PubTator3，同一口径 | F1 0.680 | 同上 |

**结论**：PubTator3 是公开系统里的强基线，也是标准资源，但不能笼统称为"当前最好"。我们的数字只能和**同一口径下的 PubTator3** 比较，不能和上面任何一个已发表的数字比较。

## 2. 评测：现在做到了什么，还缺什么

**已做到**
- 一对一匹配（最大二部匹配）已作为默认口径，有单元测试覆盖（重复预测、一条预测对应多条金标、顺序无关、空集）。每个 eval JSON 都记录了评分器版本和代码哈希，旧口径的数字可以从同一个文件还原。
- BioRED Test 补齐到全部 100 篇：另外 27 篇没有基因–疾病关系，在这 27 篇上判为 supported 的配对都按"相对金标的误报"计算。另外报告"部署口径"，即失败的论文按空输出计。

**还缺（按重要性排序）**
1. 实体识别没有单独评测（实体位置级 P/R/F1）。BioRED 金标里有实体位置，用现有输出就能零成本算出。
2. 没有 ID 标准化，因此无法按 BioCreative 的官方口径评测。
3. 没有"给定金标实体"的关系抽取设置。这个设置能把实体识别的误差和关系判断的误差分开。
4. 字符位置重叠的匹配本身可能过宽，一对一匹配不能解决这个问题。

## 3. 方法：各个组件到底贡献了什么

| 对照（BioRED，一对一匹配） | 结果 | 能下的结论 |
|---|---|---|
| V1 卡片 vs V6 最小提示（Dev+Test 143 篇） | F1 0.551 vs 0.665，差 +0.114 [0.040, 0.197]；精确率 0.809 vs 0.739（区间跨 0）；召回率 0.418 vs 0.604 | 卡片的净效果是降低 F1，主要代价在召回率 |

## 4. 初步发现：能说什么、不能说什么

**有证据支持**
- 在同一口径下，我们的系统在 BioRED 上低于 PubTator3（Test 100 篇 F1：V6 0.614，V1 0.511，PubTator3 0.680）。
- 详细的规则卡片降低了召回率和 F1；它在精确率上的优势在一对一匹配下只有约 5–7 个百分点，而且区间跨 0。
- uncertain 的原因码可以作为阈值：路由后 V1 Test F1 从 0.515 升到 0.581（原文写的是 0.542 → 0.627，需要改）。
- 两次运行之间：V6 的 F1 相同，supported 集合 Jaccard 0.87；V1 的 F1 差 0.03，Jaccard 0.79。两次运行只能说明结果大体可重复，不能估计方差。
- 部署口径的失败：V6 在 Test 100 篇中有 2 篇没有有效结果（PMID1848636 两次都被安全机制拦截）；V1 是 100/100。
- 只有 V1 判为 supported 的配对，在 Dev 上只有 5 对：V1 的结果几乎是 V6 的子集，分歧基本都是 V6 多判出来的。
- 安全机制的拦截不是固定在某篇摘要上的：PMID18457324 第一次被拦截，第二次正常完成。
- 单名作者的盲序案例审核：卡片漏掉的配对在所查的 16 条里都有原文依据（探索性，只用来解释错误类型），见下面的"人工自查"。
- 外部全文测试（BioTriplex）：输入相同时 V6 与 PubTator3 无可分辨差别；全文让召回率从 0.37 升到 0.81（同一批 25 篇），收益来自输入范围。

**人工自查（2026-11-03，`experiments/biored/self_check.py`）**

在 Dev 上，只有 V6 判为 supported 的配对共 114 对。审核包从中抽了 40 对，其中 16 对不对应任何 BioRED 金标关系。把这 16 对和 10 条对照混在一起，重新编号、打乱顺序，由一名作者在不知道每条属于哪一类的情况下标注：

| 类别 | 条目 | 判为有关系或推测性关系 |
|---|---:|---:|
| 对照：BioRED 有关系 | 5 | 5 |
| 对照：同一摘要中基因和疾病都不在任何 BioRED 关系里 | 5 | 1 |
| 有争议：只有 V6 判、BioRED 没标 | 16 | 16（15 条明确，1 条推测性） |

- 16 条的实体都标对了。只按逐条计算，"摘要陈述了关系"的比例 95% 单侧下限约 0.83。但这 16 条来自 9 篇摘要（一篇占 5 条，一篇占 3 条），有效样本量更小。
- 局限：只有一名标注者，无法计算一致性；标注者知道研究假设。要写进论文，还需要第二名独立标注者。
- 这能说明为什么 BioRED 会低估零样本 LLM 的精确率，但**不能**拿来抬高 V6 与 PubTator3 的比较：PubTator3 是按 BioRED 的口径训练的，评测时用同一份金标，两边才可比。如果要讨论，应该单独报告"超出 BioRED 标注范围的、有原文依据的关系"占多少。

**大模型评判（`experiments/biored/llm_adjudicate.py`，不能代替人工）**
- GPT-6.1 sol 和 GPT-6 luna 按相同的盲法说明完成了 85 个条目和 76 个证据包。
- 两者之间一致性接近随机（四分类 κ = 0.05，有无关系二分类 κ = −0.02）。sol 对 85 条中的 84 条都判"有关系"；luna 在对应和不对应 BioRED 金标的条目上，判"有关系"的比例都是 75%。
- 在人工自查也覆盖的 21 条上，sol 与标注者 20 条一致，luna 12 条一致。审核包里几乎没有真正无关的配对，所以 sol 的结果不一定是偏差，但两个模型都没有在阴性对照上检验过。

**还不成立**
- "引用的证据支持所报告的关系"：校验器只能证明句子存在、格式正确。第 2 轮里，大模型判 V1 的证据包几乎都"足够"，V6 的约 63–80%。但两组条目不同，不是配对比较，而且没有人工核对。
- "精确率低主要因为金标不完整"：对 V6 多判的配对有初步支持（上面的自查）；对 V1 和整体的误报还没有检验。
- 读全文的收益在 RENET2 上没有单独检验；在 BioTriplex 上已经分开（见第 0 节第 7 条）。
- 跨模型一致：GPT-6.1 Sol 在 Test 50 篇上 F1 0.523，Claude 0.521，样本只有 50 篇。

## 6. 需要你决定

1. **论文定位。** 按现有证据，建议写成"零样本、带证据的全文基因–疾病关系抽取的系统评估"：
   - 方法主体：V6 加确定性前处理，保留结构化证据输出（状态、引用句子、陈述来源）；
   - 主要发现一：在 BioRED 摘要上，零样本 LLM 不如有监督的 PubTator3；在 BioTriplex 上只读摘要时，两者无可分辨差别；
   - 主要发现二：读全文带来召回率的大幅提升（BioTriplex 上 Claude +0.45、GPT +0.58，有监督的 BioREx 也 +0.43），这一收益来自输入范围，不是 LLM 独有；
